# 安装与部署

目标是 **PvZ2 Gardendless 0.15.0 + GP-Next 1.5.0-pre.1**。

## 一、开启 JavaScript 模组

当前 GP-Next 版本只允许从开发者控制台开启 JS 模组，设置页里没有开关。

1. 进入游戏，按 `F12` 打开开发者工具
2. 切到 **Console**
3. 执行：

   ```js
   await gpNext.mods.enableJsModding()
   ```

4. 按提示应用或重启

> 本模组的连射 / 弹种 / 亡语都走 JS 钩子，这一步必须做。
> 数据补丁（数值与图鉴）本身不需要，但两者一起装才有完整体验。

## 二、导入

**ZIP（推荐给玩家）**

1. 拿到 `dist/plant-rebalance-by-yes-a-hit-4.0.0.zip`
2. GP-Next 侧栏 → **模组** → **导入 ZIP**
3. 核对名称与版本后安装

**文件夹（推荐给开发）**

1. 把仓库克隆或复制到本机
2. GP-Next 侧栏 → **模组** → **导入文件夹**
3. 选择包含 `pack.json` 的那一层 —— 本仓库的**根目录**就是

> 仓库根同时是模组根，`git clone` 之后可以直接导入，不需要额外构建。

## 三、启用（最容易漏的一步）

导入后的条目 `enabled` 默认是 `false`：

1. 在模组列表里**勾选**本模组
2. 点 **保存并应用**

**不勾选等于没装** —— 包在 `installed/` 里、配置里也有，
但 JS 一行不跑、数值补丁一条不生效。排查时先看 `configuration-state.json`
的 `enabled` 字段，别急着翻日志。

## 四、重启并验证

1. 点 **保存并应用**，看到提示后**完全退出游戏**（不是回主菜单）
2. 重新启动，进入任意关卡
3. 打开 GP-Next → **模组** → 点本模组名称，确认面板里各条钩子都有值

**不需要任何额外脚本、命令行或补丁工具。**

> 少数 GP-Next 构建在「保存并应用」后重启会停在
> `启动已停止（afterProject）。Native build identity is unavailable`。
> 那是该构建拿不到 `Native build identity`、导致配置应用环节失败，
> **导入任何模组都可能触发，与本模组无关**。处理方式见第七节。

## 五、更新

重新导入新 ZIP 即可。**注意 uuid 变过** ——
更名前的版本是 `yg.pea-rebalance`，现在叫 `yes-a-hit.plant-rebalance`，
两者在 GP-Next 眼里是**两个不同的模组**。

从旧版升级的话：装上新包、勾选、保存应用，然后把旧的
`yg.pea-rebalance` 取消勾选（或直接不引用）。不要两个同时启用。

**不要直接改 `installed\<hash>\` 里的文件** —— 会触发

```
Package digest does not match stored bytes
```

安装目录名就是包内容摘要（算法未公开）。改包必须重新导入，让 GP-Next 重算。

## 六、数据目录

| 项 | 位置 |
|---|---|
| 数据目录 | `%APPDATA%\com.pvzge.game\gp-next\` |
| 配置状态（唯一权威） | 上述目录下 `configuration-state.json` |
| 已安装包 | `gp-next\installed\<sha256>\` |
| 存档备份 | `gp-next\save-backups\native-player\` |

## 七、排查

模组详情面板里有完整状态：各条钩子的挂载结果、发射/连射计数与触发率、
以及当前生效的关键数值。

| 现象 | 先看哪里 |
|---|---|
| 完全没反应 | 模组列表里勾没勾；`configuration-state.json` 的 `enabled` |
| 数值没变 | 数据补丁**需要重启**；JS 钩子只影响运行时新建 / 更新的实例 |
| 连射不触发 | 面板里的触发率是 0 还是接近概率值 —— 后者说明只是运气 |
| 弹种没变化 | 面板里各钩子的「已挂载」；某个植物类可能没定位到 |
| 某个植物没效果 | 日志搜 `综合平衡`，看该条是否报「未定位到类」 |

### 已知问题：重启后停在「启动已停止（afterProject）」

```
启动已停止（afterProject）。Native build identity is unavailable
```

**原因**：部分 GP-Next 构建拿不到 `Native build identity`，导致「保存并应用」时
把 `desired` 落到 `active` 的那一步失败；失败之后配置状态不追平，
于是每次启动都撞同一个错。**导入任何模组都可能触发，与本模组无关。**

**处理**：按提示进入**恢复配置界面**，选择返回上次可用的配置，
游戏即可正常启动，存档不受影响。不要反复清空存档 —— 那解决不了这个问题。

### 其它

- 报错时把日志里以 `[综合平衡]` 开头的行一并附上，定位会快很多。
- 游戏版本升级后若出现异常，先到 GP-Next 的 **数据** 页重新导出一次，
  比对字段有没有变化（尤其是 `ShootInterval` 这类可能是区间对象的字段）。
