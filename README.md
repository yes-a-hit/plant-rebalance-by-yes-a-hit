# Plant Rebalance by yes-a-hit

> 面向 PvZ2 Gardendless 的综合平衡包：**11 种植物的概率弹种 / 多发 / 开大**、
> **高坚果的死亡亡语**、**33 种植物的价格与数值调整**，
> 并把全部改动**同步写进游戏内图鉴**（46 株各加一条「平衡改动」说明）。
>
> 除此之外，本包还刻意保留了数条**由代码串扰产生的「特性」** —— 见下。

| | |
|---|---|
| 版本 | 4.0.0 |
| 适配 | PvZ2 Gardendless 0.15.0 + GP-Next 1.5.0-pre.1 |
| 前置 | 无（需要开启 JavaScript 模组） |
| uuid | `yes-a-hit.plant-rebalance` |

## 特性

这个模组里有几处效果**不是刻意设计出来的**，而是钩子互相串扰的副产品。

它们在测试中被发现之后**没有修掉，而是当成特性保留了下来** ——
因为它们让游戏变得更有意思，虽然可能破坏平衡，但作者采用了涨价处理。

### 1. 所有豌豆都能连射

连射的实现方式：在植物的发射事件里按概率**额外调用一次 `_shoot()`**。
`_shoot` 是豌豆系共有的方法，**各植物把自己的实现覆写在上面**。

于是只要一只植物进了连射名单，它触发的那次额外发射**走的是它自己的 `_shoot`** ——
结果所有豌豆系植物都获得了连射能力，**包括原本不该有的那些**。

这不是缺陷，是新的取舍：豌豆系之间因它有了不同的手感。

### 2. 豌豆迫击炮的特殊攻击被超级豌豆迫击炮继承

同源：超级豌豆迫击炮在触发连射时，**继承了普通豌豆迫击炮的特殊攻击逻辑**。
两级迫击炮因此手感连贯，而不是各自孤立的两只植物。

### 3. 豌豆藤涨到 175 阳光，在连射下反而意外平衡

因为连射的存在，豌豆藤的性价比被整体抬高了：

- **原版 125 阳光** = 用 125 块买到「1.5 个豌豆射手」的产出，而且能buff同一格的所有豌豆，**太划算**
- **本包 175 阳光**：在连射环境下，这个价位**恰好落在合理区间**

所以这条不是「削弱」，而是**配合连射特性做的再平衡**。

## 快速开始

1. 游戏内按 `F12`，在 Console 执行一次 `await gpNext.mods.enableJsModding()`
2. 取得安装包 ZIP —— 在 **Releases** 页面下载，或克隆本仓库后运行 `npm run pack` 自行打包
3. GP-Next 侧栏 → **模组** → **导入 ZIP**，选中上一步得到的 zip
4. **在模组列表里把它勾上**（导入后默认不勾，**不勾等于没装**）
5. 点 **保存并应用**，按提示重启游戏

**不需要任何额外脚本、命令行或补丁工具。**

> **第 4 步最容易漏。** 包导入后在 `installed/` 和配置里都在，但 `enabled` 是 `false`，
> 此时 JS 一行不跑、数值补丁一条不生效，表现就像"没装"。

遇到问题见 [`docs/INSTALL.md`](docs/INSTALL.md)。

## 改动一览

### A. 概率弹种（加权替换 `PeaType`）

| 植物 | 弹种表 |
|---|---|
| 豌豆迫击炮 `slingpea` | 50% 普通豌豆 / 40% 原始大豌豆（60 伤）/ 10% 椰子炸弹 |
| 双发射手 / 三发射手 / 裂荚射手 | 70% 普通豌豆 / 15% 火焰豌豆 / 15% 寒冰豌豆 |
| 寒冰射手 `snowpea` | 90% 寒冰豌豆 / 10% 雪滴花冰锥 |
| 豌豆荚 `peapod` | 按档位分配弹种 |
| 充能柚子 `citron` | 概率弹种 |

**注意**：投射物型弹种（如爆裂莓）**不能进投掷路径** —— 豌豆迫击炮走的是
`lobOneCabbageOnZombie`，塞进去会打不出伤害。所以弹种表只用直线型。

### B. 概率多发（连射）

| 植物 | 触发概率 | 额外发数 |
|---|---|---|
| 豌豆射手 | 10% | +3 |
| 毒液豌豆 | 20% | +2 |
| 火焰豌豆 | 20% | +2（同步换蓝火） |
| 电能豌豆 / 充能柚子 / 高坚果 | 各自配置 | — |

### C. 概率开大

电能豌豆 / 充能柚子：概率把弹种换成 `PeaTypePlantfood`。
**只换类型，不触发无敌效果。**

### D. 数值调整（39 条数据补丁）

常用的几项：

| 植物 | 项目 | 原值 | 新值 |
|---|---|---|---|
| 豌豆迫击炮 | 阳光 | 125 | **250** |
| 豌豆迫击炮 | 攻击间隔 | 4 秒 | **4.2–4.5 秒** |
| 机枪射手 | 阳光 | 450 | **400** |
| 菜问 | 阳光 | 150 | **100** |
| 闪电芦苇 | 阳光 / 伤害 | 125 / 10 | **150 / 15** |
| **豌豆藤** | 阳光 | 125 | **175**（见特性 3） |
| 原始坚果墙 | 血量 / 护甲 | 4000 | **5000** |
| 甜椒投手 | 伤害 | 50 | **80** |
| 心之花 | 伤害 | 40 | **60** |

完整清单见 [`jsons/objects/PlantProps.json`](jsons/objects/PlantProps.json)（39 条）
与 [`jsons/objects/ProjectileProps.json`](jsons/objects/ProjectileProps.json)（8 条）。

### F. 图鉴同步

上面每一条改动都写进了游戏内图鉴 —— 46 株植物各新增一条「平衡改动」说明，
并按新数值修正了图鉴里显示的伤害数字。看
[`jsons/objects/PlantAlmanac.json`](jsons/objects/PlantAlmanac.json)。

## 项目结构

仓库根**同时就是模组根** —— `pack.json` 在最顶层，所以 `git clone` 之后可以直接用
GP-Next 的「导入文件夹」选中仓库根，不需要额外构建步骤。

```
plant-rebalance-by-yes-a-hit/
├── pack.json              GP-Next 模组清单
├── jsons/objects/         数据补丁：植物数值 / 投射物伤害 / 图鉴
├── scripts/main.js        运行期入口：四类钩子（ESM）
├── tests/                 模拟验收测试（不需要游戏本体）
├── tools/pack.ps1         发布打包：白名单 + 校验 + 用产物复测
├── docs/
│   ├── INSTALL.md         安装、部署与排查
│   └── ENGINE-NOTES.md    引擎笔记：每条改动挂在哪、为什么
├── package.json           仅开发用（`type: module` + npm scripts）
├── LICENSE                MIT 全文
├── NOTICE.md              非代码内容的来源与归属
└── CHANGELOG.md
```

发布的 ZIP **只含运行时文件**
（`pack.json` + `README.md` + `LICENSE` + `NOTICE.md` + `jsons/` + `scripts/`），
`tests/`、`tools/`、`docs/`、`package.json` 等开发用文件不会进包。

## 自定义

四类目标组都在 `scripts/main.js` 顶部：

| 想改什么 | 数组 |
|---|---|
| 概率弹种 | `WEIGHT_TARGETS` |
| 概率连射 | `EXTRA_SHOT_TARGETS` |
| 概率开大 | `FOOD_TARGETS` |
| 死亡亡语 | `DEATHRATTLE_TARGETS` |

数值改动走 `jsons/objects/*.json`，改完跑一遍 `npm test`。

> **改 `ShootInterval` 时要保持原结构类型** —— 它既可能是数字，也可能是
> `{ Min, Max }` 区间对象，引擎侧走 `getRandomFromRange`。

游戏内面板能看到各条钩子的命中统计（发射次数 / 连射次数 / 触发率）。

## 已知限制

- **数值补丁需要重启生效**；运行期钩子只影响运行时新建或更新的实例。
- **投射物型弹种不能进投掷路径**：`blastberry` 这类自带 `ShotCount`/`ShotType` 的
  弹种，被 `slingpea` 的 `lobOneCabbageOnZombie` 处理后**打不出伤害**。
- 若某个植物类在未来版本改了方法名，对应那条会挂载失败，日志与面板会写明是哪一个。
- 本项目由vibe coding实现，可能对不上，反正能run就行
